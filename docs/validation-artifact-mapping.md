# Validation Artifact Mapping: V-Model to AWS Implementation

> **Purpose:** This document maps traditional V-model validation deliverables to their automated AWS implementations within the GxP Compliance Automation framework. It defines how each validation document is generated, stored, and linked to form a complete, audit-ready validation package.

---

## 1. V-Model Artifact Mapping

The following table maps each V-model validation document to its corresponding AWS implementation, generation method, and storage location.

| V-Model Document | AWS Implementation | Generated By | Storage Location | Format |
|---|---|---|---|---|
| **Validation Plan (VP)** | Markdown document in CodeCommit repository | Manual (version controlled) | Source repository (`docs/validation-plan.md`) | Markdown |
| **User Requirements Specification (URS)** | Requirements in repo + linked Jira/ticket references | Manual | Source repository (`docs/urs.md`) | Markdown + ticket links |
| **Functional Requirements Specification (FRS)** | CloudFormation template parameters + design documents | Manual / partially generated from templates | Source repository (`docs/frs.md` + `templates/`) | Markdown + YAML |
| **Design Specification (DS)** | Architecture Decision Records (ADRs) + CloudFormation templates | Manual | Source repository (`docs/adr/`) | Markdown + YAML |
| **Requirements Traceability Matrix (RTM)** | Auto-generated from pipeline metadata, linking requirements → tests → results | Automated (pipeline post-processing Lambda) | S3 artifact bucket (`gxp-rtm/`) | JSON + rendered PDF |
| **IQ Protocol & Report** | JSON output from IQ Verification Lambda — infrastructure state vs. specification | Automated | S3 (`gxp-iq-reports/{system}/{timestamp}/`) | JSON |
| **OQ Protocol & Report** | JUnit XML test results from CodeBuild OQ stage | Automated | S3 (pipeline artifact bucket, `oq-results/`) | JUnit XML + HTML |
| **PQ Protocol & Report** | Performance/load test results from CodeBuild PQ stage | Automated | S3 (pipeline artifact bucket, `pq-results/`) | JSON + JUnit XML |
| **Validation Summary Report (VSR)** | Compiled from all above artifacts + electronic signatures | Semi-automated (Lambda compilation + e-signature approval) | S3 + DynamoDB (signature records) | PDF + JSON metadata |
| **Change Control Record** | Git commit history + CodePipeline execution metadata | Automated | CodeCommit + S3 (pipeline artifacts) | Git log + JSON |
| **Periodic Review** | Scheduled Config compliance evaluation + Security Hub summary | Automated (EventBridge scheduled rule) | S3 (`gxp-periodic-reviews/`) | JSON + PDF |

## 2. Detailed Artifact Descriptions

### 2.1 Validation Plan (VP)

**Source:** `docs/validation-plan.md` in CodeCommit

The validation plan is maintained as a version-controlled Markdown document. It defines:
- Scope of validation
- Validation approach and strategy (aligned to FDA CSA risk-based thinking)
- Roles and responsibilities
- Acceptance criteria
- Deliverable list with traceability to this mapping document

**Versioning:** Git history provides full version control with author attribution and timestamps.

### 2.2 Requirements Traceability Matrix (RTM)

**Generated by:** `src/rtm-generator/` Lambda function, triggered at pipeline completion

The RTM is automatically generated by parsing:
1. Requirements IDs from `docs/urs.md` and `docs/frs.md` (tagged with `[REQ-XXX]` markers)
2. Test case IDs from test file docstrings and JUnit XML output
3. Pipeline execution results linking test pass/fail to requirement coverage

**Schema:**
```json
{
  "rtm_version": "1.0",
  "generated_at": "2026-07-27T10:30:00Z",
  "system": "gxp-compliance-automation",
  "entries": [
    {
      "requirement_id": "URS-001",
      "requirement_text": "System shall encrypt all data at rest using AES-256",
      "frs_reference": "FRS-012",
      "test_cases": ["test_kms_encryption_enabled", "test_s3_bucket_encryption"],
      "iq_evidence": "iq-report-2026-07-27T10:25:00Z.json",
      "oq_evidence": "oq-results/TEST-SUITE-encryption.xml",
      "status": "PASSED",
      "last_verified": "2026-07-27T10:28:00Z"
    }
  ]
}
```

### 2.3 IQ Report

**Generated by:** `src/iq-verification-lambda/handler.py`

The IQ verification Lambda validates deployed infrastructure against the specification defined in CloudFormation templates. It checks:
- Resource existence and configuration (KMS key policies, S3 bucket settings, IAM roles)
- Parameter values match expected specifications
- Network configuration compliance (VPC, security groups, NACLs)
- Encryption configuration at rest and in transit

**Output location:** `s3://ARTIFACT_BUCKET/gxp-iq-reports/{system-name}/{execution-id}/iq-report.json`

### 2.4 OQ Report

**Generated by:** CodeBuild project in pipeline OQ stage

Operational Qualification executes functional tests that verify the system operates as specified under normal conditions. Tests are written in pytest and output JUnit XML.

**Output location:** `s3://ARTIFACT_BUCKET/oq-results/{execution-id}/`

### 2.5 PQ Report

**Generated by:** CodeBuild project in pipeline PQ stage

Performance Qualification executes load and stress tests to verify the system performs acceptably under expected production conditions.

**Output location:** `s3://ARTIFACT_BUCKET/pq-results/{execution-id}/`

### 2.6 Validation Summary Report (VSR)

**Generated by:** VSR compilation Lambda + e-signature workflow

The VSR is a compiled PDF that aggregates:
- Validation plan reference
- RTM (with all entries in PASSED state)
- IQ summary with pass/fail counts
- OQ summary with test coverage metrics
- PQ summary with performance benchmarks
- Deviation list (if any)
- Conclusion and recommendation for release

The VSR requires electronic signature from:
1. Validation Lead
2. Quality Assurance
3. System Owner

### Audit Trail Integrity

Each artifact stored in S3 includes:
- **S3 Object Lock** (GOVERNANCE or COMPLIANCE mode) preventing deletion or modification
- **S3 Versioning** providing version history
- **KMS encryption** with the GxP compliance key
- **CloudTrail data events** logging all access
- **SHA-256 hash** stored in DynamoDB for independent integrity verification

## 4. Retrieving the Complete Validation Package

### For a Regulatory Inspector

> **Prerequisite:** Before running these commands, identify your artifact bucket name from the
> deployed CloudFormation stack outputs:
> ```bash
> export ARTIFACT_BUCKET=$(aws cloudformation describe-stacks \
>   --stack-name <your-pipeline-stack> \
>   --query 'Stacks[0].Outputs[?OutputKey==`ArtifactBucketName`].OutputValue' \
>   --output text)
> ```



To retrieve the complete validation package for a given system release:

```bash
# 1. Identify the pipeline execution for the release
aws codepipeline list-pipeline-executions \
  --pipeline-name gxp-validation-pipeline \
  --query 'pipelineExecutionSummaries[?status==`Succeeded`]' \
  --output table

# 2. Set the execution ID
EXECUTION_ID="abc123-def456-ghi789"

# 3. Download all artifacts for that execution
aws s3 sync \
  s3://${ARTIFACT_BUCKET}/gxp-iq-reports/system/${EXECUTION_ID}/ \
  ./validation-package/iq/

aws s3 sync \
  s3://${ARTIFACT_BUCKET}/oq-results/${EXECUTION_ID}/ \
  ./validation-package/oq/

aws s3 sync \
  s3://${ARTIFACT_BUCKET}/pq-results/${EXECUTION_ID}/ \
  ./validation-package/pq/

aws s3 cp \
  s3://${ARTIFACT_BUCKET}/gxp-rtm/${EXECUTION_ID}/rtm.json \
  ./validation-package/rtm/

aws s3 cp \
  s3://${ARTIFACT_BUCKET}/gxp-vsr/${EXECUTION_ID}/validation-summary-report.pdf \
  ./validation-package/vsr/

# 4. Retrieve signature audit records
aws dynamodb query \
  --table-name gxp-e-signatures \
  --key-condition-expression "ExecutionId = :eid" \
  --expression-attribute-values '{":eid":{"S":"'${EXECUTION_ID}'"}}' \
  --output json > ./validation-package/signatures/audit-trail.json

# 5. Retrieve CloudTrail events for the execution timeframe
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventSource,AttributeValue=codepipeline.amazonaws.com \
  --start-time "2026-07-27T00:00:00Z" \
  --end-time "2026-07-27T23:59:59Z" \
  --output json > ./validation-package/cloudtrail/pipeline-events.json
```

### Automated Package Generation

For convenience, the system includes an **Inspector Package Lambda** that compiles all artifacts into a single ZIP:

```bash
# Trigger package generation
aws lambda invoke \
  --function-name gxp-inspector-package-generator \
  --payload '{"execution_id": "abc123-def456-ghi789", "system": "batch-record-system"}' \
  --output json \
  response.json

# The Lambda returns a pre-signed URL to download the complete package
cat response.json | jq -r '.body.download_url'
```

## 5. Artifact Retention

| Artifact Type | Retention Period | Mechanism | Regulatory Basis |
|---|---|---|---|
| Validation Plan | Life of system + 7 years | S3 Object Lock (GOVERNANCE) | 21 CFR 211.180 |
| IQ/OQ/PQ Reports | Life of system + 7 years | S3 Object Lock (GOVERNANCE) | 21 CFR 211.68 |
| RTM | Life of system + 7 years | S3 Object Lock (GOVERNANCE) | 21 CFR 211.68 |
| VSR | Life of system + 7 years | S3 Object Lock (GOVERNANCE) | 21 CFR 211.180 |
| Audit Trail | Life of system + 7 years | DynamoDB + S3 archive | 21 CFR Part 11.10(e) |
| E-Signature Records | Life of system + 7 years | DynamoDB + S3 archive | 21 CFR Part 11.50 |
| Source Code | Indefinite | CodeCommit (full history) | Best practice |
